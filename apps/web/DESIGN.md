# Design System: Hanza

## Overview

**Creative North Star: "The Dispatch Desk"**

The Hanza panel is the commerce admin a Shopify-fluent team trusts on sight. It does not try to be a visual world of its own: by the owner's decision it follows the category standard for commerce admins, built on shadcn/ui, and is judged against Shopify Admin. A gray canvas carries white bordered cards; a collapsible sidebar groups destinations by the job they serve; a top bar holds breadcrumbs and a command palette. Familiarity is the feature. A warehouse picker, a customer-service agent and an owner each spend whole working days here, and none of them should have to learn the furniture.

What the system does insist on is order of attention. What needs a person leads every screen: the dashboard opens with a Needs attention list instead of KPI cards, sidebar items carry counts of what waits behind them, and state is always written out in words beside a shape and a tone. Neutrals carry no hue at all; colour is reserved for links, focus and state, so that when colour appears it means something happened.

Density is that of a working tool: 14px body text, 32px controls, 44px table rows, 20px between blocks. Everything is tokenised for light and dark, and everything is translated (English and Polish), so no screen hard-codes a colour or a sentence.

The name of the North Star is provisional: it was chosen while recording the build and has not been confirmed by the owner.

**Key Characteristics:**

- Category-standard commerce admin on shadcn/ui; quality bar Shopify Admin.
- Achromatic neutrals; blue only for links, focus and selection; eight hues only for state.
- One raised surface (white card, 1px border, hairline shadow) on a gray canvas.
- One near-black primary action per page, top-right in the page header.
- State is always tone plus icon shape plus text.
- Tables follow the width of their container, not the window.
- Light and dark from one token set; copy only from the message catalogues.

## Colors

A grayscale interface with a single blue for interaction and eight low-chroma hues that speak only for state. All values are OKLCH custom properties in `src/app/globals.css`; the frontmatter lists the light value under each name and the dark value under the same name with a `-dark` suffix.

### Primary

- **Ink** (`primary`): the fill of the page's one primary button, checked checkboxes and the on state of a switch. Near-black in light, near-white in dark; it inverts with the theme and its text (`primary-foreground`) inverts with it.

### Secondary

- **Link Blue** (`link`): text links inside content and the link button. Always medium weight, underlined on hover.
- **Focus Blue** (`ring`): the one focus outline, the text caret, and (at reduced alpha, `selection`) the text selection. Lighter and less saturated in dark so it holds 3:1 against dark surfaces.

### Tertiary

The eight status hues: gray, blue, teal, green, amber, orange, red, violet. Each exists as a triple in both themes: a **strong** colour for text and icons (`status-<hue>`), a **subtle** fill (`status-<hue>-subtle`) and a matching **border** (`status-<hue>-border`). Every strong colour passes 4.5:1 on its own subtle fill, on a card and on the canvas, in both themes.

They are used under two vocabularies that share the same values:

- **Six semantic tones**, the panel's vocabulary for state: `neutral` (gray), `info` (blue), `success` (green), `warning` (amber), `attention` (orange), `critical` (red). Classes follow `text-<tone>`, `bg-<tone>-subtle`, `border-<tone>-border`.
- **Eight Order status colours**, the labels an organization may give its own Order statuses: all eight hues by name (`status-gray` … `status-violet`). Teal and violet exist only here. A status without a colour of its own takes its phase's: new is blue, processing is amber, shipped is green, cancelled is gray.

`destructive` is the saturated red of the base shadcn token, with `destructive-foreground` (white) on it. On a page, danger is the `critical` tone (the danger button is an outline in critical red); the solid red fill appears in one place only, the confirm button of the alert dialog that follows a danger button.

### Neutral

- **Canvas** (`background`): the page behind everything, and the sticky top bar.
- **Card** (`card`): the one raised surface; also the fill of inputs and outline buttons. `popover` equals it in light and sits one step lighter in dark, so floating layers separate from cards.
- **Foreground** (`foreground`): all primary text. `card-foreground`, `popover-foreground`, `secondary-foreground` and `accent-foreground` are the same value.
- **Muted Foreground** (`muted-foreground`): descriptions, hints, column headers, timestamps, the empty-value dash. Passes 4.5:1 on canvas, card and sidebar.
- **Muted** (`muted`), **Accent** (`accent`), **Secondary** (`secondary`): three close steps of quiet fill. Muted (at 60%) tints table headers and row hover; accent is the hover of outline and ghost buttons; secondary is their pressed state.
- **Border** (`border`): every hairline: card edges, row dividers, section header rules. It is the default border colour of every element.
- **Border Strong** (`border-strong`): the edge of outline buttons, the dashed edge of an inactive filter chip, timeline dots.
- **Input** (`input`): the edge of text controls and checkboxes, deliberately darker than `border` so a control's boundary passes 3:1.
- **Sidebar** (`sidebar`, `sidebar-accent`, `sidebar-border`): the sidebar is one step darker than the canvas in both themes; its hover fill is `sidebar-accent`, and the current item is a card-coloured tile.
- **Overlay** (`overlay`): the scrim behind dialogs and the mobile sidebar sheet.

### Named Rules

**The Tokens Only Rule.** Screens style with the semantic tokens and nothing else: no raw palette classes (`bg-red-500`, `text-slate-600`), no hex, no `white` or `black`. A new colour need is a new token in both themes, or it is not needed.

**The Colour Means State Rule.** Neutrals carry no hue. Blue belongs to links, focus and selection; the eight status hues belong to state. No hue is used for decoration, emphasis or branding inside the panel.

**The Never Colour Alone Rule.** A tone is never the only signal. It is always paired with an icon shape and with text, so a state reads in grayscale and to a screen reader.

## Typography

**Display Font:** none; the panel has no display face.
**Body Font:** Inter Variable, self-hosted through `@fontsource-variable/inter` (with ui-sans-serif, system-ui, -apple-system, Segoe UI, Roboto, Helvetica Neue, Arial, sans-serif)
**Label/Mono Font:** the platform monospace stack (ui-monospace, SF Mono, SFMono-Regular, Menlo, Consolas, Liberation Mono, monospace)

**Character:** One sans at a narrow range of sizes; hierarchy comes from weight (400, 500, 600) and from muted versus full foreground, not from scale. Numbers that are compared sit in tabular figures.

### Hierarchy

- **Headline** (600, 1.25rem / 1.75rem, -0.01em): the page's only `<h1>`, in the page header, on the auth cards and on whole-page states. Wraps anywhere rather than widening the page.
- **Title** (600, 0.875rem / 1.25rem): section and card headings (`<h2>`), empty-state titles, notice titles. A dialog title is the one step up (600, 1rem / 1.5rem).
- **Body** (400, 0.875rem / 1.25rem): the default for everything. Running text (descriptions, hints, notes) is capped at the `max-w-measure` utility, 54ch, about 70 characters of Inter. Text controls render at 1rem below the `md` viewport breakpoint so mobile browsers do not zoom on focus, and at 0.875rem from there up.
- **Label** (500, 0.875rem / 1.25rem): form labels, buttons, primary cells and row titles, link text.
- **Meta** (400, 0.8125rem / 1.125rem; token `--text-meta`): section descriptions, field hints and errors, the quiet line under a title or a table's primary cell, description-list terms. At weight 500 it is the column header, the filter tab, the filter chip and the small button.
- **Caption** (500, 0.75rem / 1rem): badges, sidebar group labels and counts; at weight 400, timeline timestamps, tooltips and keyboard hints.
- **Mono** (400, 0.8125rem / 1.125rem): identifiers only, see the rule below.

### Named Rules

**The Identifier Rule.** Monospace is for identifiers and nothing else: SKUs, external ids, connection ids, codes, environment variable names. They are set through the `Identifier` component (or `TextLink mono`), stay on one line in a table column, and may break anywhere in a narrow place. The face is the platform monospace stack, not a self-hosted one: a deliberate exception, because adding a production dependency needs the owner's approval and Operate mode permits system stacks.

**The Order Number Rule.** An Order number is not an identifier in this sense. People read it out and type it, so it is set in Inter with proportional figures (`orderNumberClass`, `normal-nums`). Tabular figures would widen Inter's hyphen ("fake - order - 1"), and Order numbers are read, not summed down a column.

**The Tabular Rule.** Quantities and amounts are right-aligned in tabular figures so digits line up down a column; dates, counts and pagination summaries take tabular figures without the alignment.

**The Real Minus Rule.** A negative number is written with the typographic minus (U+2212), which is as wide as a digit in tabular figures, never with the hyphen `Intl` produces. The formatters in `src/lib/format.ts` do this; screens never format numbers or money by hand.

**The Empty Value Rule.** A value that is not there is an em dash in muted foreground with words for a screen reader (`NoValue`). Never an empty cell, never "N/A", never a bare hyphen.

## Layout

**Shell.** A left sidebar (16rem; collapsible to a 3rem icon rail, the choice kept in a cookie so the page does not shift after hydration; an 18rem sheet over the page on small screens) and an inset main area. The main area has a sticky 48px top bar on the canvas colour with a hairline below it: sidebar toggle, breadcrumbs (group, destination, named sub-pages; only the end of the trail below 640px), and the command palette trigger at the right. Content is centred in a column of at most 75rem with 16px side padding, 24px from 640px and 32px from 1024px, and 20px above and below. A skip link to the main content is the first focusable element.

**Rhythm.** Every page is one column at a 20px gap: page header, then cards. Cards pad 16px; a section header pads 12px by 16px over a hairline; a field stack (label, control, note) gaps 6px; groups of actions gap 8px.

**The list page skeleton** (reference: Orders). Page header with the title and, top-right, the page's primary action. One `Panel` (a card without a heading, since the `<h1>` names it) holding a filter bar, then the table or an empty state. Pagination sits below the card on the canvas: a summary at the left, previous and next at the right. Filters live in the URL as links and GET forms, so they survive a reload and can be shared.

**The detail page skeleton** (reference: an Order). Page header with a back arrow to the list, the title, state badges beside it, one quiet meta line of facts under it, and actions at the right. Below, `PageColumns`: a main column of sections beside a 21rem aside, with long logs (a history) continuing the main column under it. Below a 64rem page container it becomes one column in reading order: main, aside, logs.

**Container queries, not viewport queries.** Pages and tables respond to the width of the place they are in, so layouts hold whether the sidebar is open or collapsed.

- A table at **56rem and wider** is a full table.
- **Below 56rem** it is still a table, without the columns marked as hidden at medium width. What those columns said folds into a quiet meta line under the row's primary cell, shown exactly while the columns are hidden, items separated by a middle dot.
- **Below 42rem** the header row is gone and every row is a stacked block of three columns: an optional checkbox, the primary cell (what the row is), and at the end its state or key number. Every other cell is a line of its own underneath, with its column's name in front of it where a label was given. Long SKUs and Order numbers break rather than push the row wider than the screen.
- The detail page splits into two columns at a 64rem page container; the dashboard's pair of sections at 48rem; a timeline moves its timestamp onto the title's line at 28rem.

**Loading.** A `loading.tsx` renders `PageSkeleton`, the outline of the page on its way so nothing jumps when it arrives: `list` is a header bar over one card of eight 44px rows; `detail` is a header over the two columns, two cards each. Skeleton blocks pulse at 8% foreground, and a visually hidden status line says the page is loading.

**Outside the panel.** Sign in, register and onboarding share one frame: the mark and the name above a single centred card (at most 24rem wide, 24px padding) on the canvas, with the language switcher beneath.

### Named Rules

**The One Primary Rule.** A page has one near-black primary button. It sits top-right in the page header, or it is the submit of a focused create or commit form. In-place saves on detail and settings pages are outline buttons everywhere, however many there are.

**The Warehouses Exception.** The Warehouses list keeps its inline two-field create form as the page's one primary, instead of a header action leading to a create page. This is deliberate: routes were not to change in this build.

**The Needs A Person First Rule.** On any screen that summarises, what waits for a person comes before totals. The dashboard opens with the Needs attention list; Orders by phase and Connection health follow, then recent activity.

## Elevation & Depth

Nearly flat. Depth is carried by tone (gray canvas, white card) and a 1px border; the shadow under a card is a hairline that sharpens its lower edge rather than lifting it. Only layers that float over the page cast a real shadow. In dark the card shadow reduces to a single 1px line and separation comes from lightness steps: sidebar, canvas, card, popover, each lighter than the last.

### Shadow Vocabulary

- **Card** (`box-shadow: 0 1px 0 0 oklch(0 0 0 / 0.04), 0 1px 3px -1px oklch(0 0 0 / 0.08)`; dark `0 1px 0 0 oklch(0 0 0 / 0.2)`): cards, sections, panels, and the current item in the sidebar.
- **Overlay** (`box-shadow: 0 4px 6px -2px oklch(0 0 0 / 0.06), 0 12px 28px -6px oklch(0 0 0 / 0.16)`; dark `0 4px 6px -2px oklch(0 0 0 / 0.3), 0 12px 28px -6px oklch(0 0 0 / 0.5)`): dialogs, popovers, menus, the command palette.
- **Control** (Tailwind's `shadow-xs`, `0 1px 2px 0 rgb(0 0 0 / 0.05)`): filled and outline buttons, inputs, checkboxes.
- **Scroll shade** (`--scroll-shadow`, a 10px gradient): the edge of a list that scrolls inside a popover, shown only on an edge that has more beyond it.

### Named Rules

**The One Surface Rule.** The card is the panel's one raised surface. Never nest two: inside a card, structure comes from hairlines, a muted fill or a toned notice.

**The One Ring Rule.** Everything a keyboard can reach shows the same focus ring: a 2px solid outline in Focus Blue, offset 2px. A component overrides it only to move it inside its own box, where a clipped edge would otherwise cut it off (whole-row links in a card use a -2px offset).

## Shapes

Gently rounded and consistent. One base radius (8px) and three steps derived from it:

- **8px** (`lg`): cards, sections, buttons, text controls, notices, popovers, sidebar items. The default; when in doubt, this.
- **6px** (`md`): small things inside those: filter tabs, skeleton blocks, tooltips, the dialog close button.
- **4px** (`sm`): checkboxes, keyboard-key hints, the focus shape of an inline link.
- **12px** (`xl`): dialogs only.
- **Full**: anything that states a state or a toggle: badges, filter chips, the switch, sidebar counts, timeline dots, the icon disc of an empty state.

Borders are 1px throughout. Cards clip their content, so tables and lists sit flush against the card's edges and take its corners. The only dashed line is the edge of an inactive filter chip, which turns solid on hover and when on.

Icons are Lucide outlines at 16px beside text (14px inside badges and inline warnings, 20px in the 40px disc of an empty state), always decorative and hidden from assistive technology, since the text beside them carries the name.

## Components

Motion is uniform across components: colour transitions of 150ms on `cubic-bezier(0.2, 0, 0, 1)`; overlays fade and scale from 95% in the same time. Under `prefers-reduced-motion` all animation and transition durations collapse.

### Buttons

Compact and quiet; the label does the work.

- **Shape:** 8px corners, 32px high, 12px side padding, medium-weight body text, 6px between an icon and its label.
- **Sizes:** small 28px (meta text, 10px padding) for table rows and filter bars; default 32px; large 36px (16px padding) for the full-width submit on auth pages. Icon-only buttons are squares of the same heights.
- **Primary:** Ink fill with inverted text; hover 85% and pressed 75% of the fill. One per page (The One Primary Rule).
- **Secondary (outline):** card fill, Border Strong edge; hover Accent, pressed Secondary. Every in-place save, every pagination link, every non-primary action.
- **Danger:** an outline too: card fill, critical border and text, critical-subtle fill on hover. Destructive actions confirm in an alert dialog before they run.
- **Ghost:** no fill or border until hovered; the back arrow, row-level icon actions, "Clear filters".
- **Pending:** while its action runs a button shows a spinning loader before its label and is disabled. Disabled is 50% opacity.
- **Links that look like buttons** take the same classes through `buttonClass`.

### Badges

A badge states something's state in words.

- **Style:** a 22px pill, 1px border, caption text at weight 500, 8px side padding, a 14px icon first. Fill, border and text are a tone's subtle, border and strong colours.
- **The Badge Rule.** A badge is tone plus icon shape plus text. Each tone has its own shape (info: circled i; success: circled check; warning: triangle; attention: circled exclamation; critical: octagon), so a badge reads without its colour. Only a neutral tag ("Default", "Inactive") may go without an icon.
- **Order status badges** take their colour from the organization's label and their shape from the fixed phase, whatever the colour: new is a circle, processing a dashed circle, shipped a circled check, cancelled a slashed circle.
- **Connection health** pairs unknown with a question circle (neutral), ok with a circled check (success), failing with an octagon (critical), expired sign-in with a key (warning).
- Badges keep the baseline of their text, so they sit level in a sentence or a table row aligned on baselines.

### Cards / Containers

- **Corner Style:** 8px, content clipped.
- **Background:** Card on Canvas.
- **Shadow Strategy:** the hairline Card shadow (see Elevation).
- **Border:** 1px Border.
- **Section:** a card that is a region named by its heading: a header (title in Title type, optional meta-size description, actions at the right) over a hairline, then content flush to the edges. Tables and lists go straight in; anything else is wrapped in 16px of padding.
- **Panel:** the same card without a header, for the table of a list page.

### Inputs / Fields

- **Style:** card fill (a 15% tint of Input in dark), 1px Input border, 8px corners, 32px high, 10px side padding, the Control shadow. Input, textarea and native select share one class, so every text control has one height, border and invalid state. Compact controls (28px, meta text) are for table rows and filter bars.
- **Hover / Focus:** the border darkens on hover; focus is The One Ring.
- **Error / Disabled:** an invalid control takes a critical border, and its note below turns critical with a small alert icon, replacing the hint. Disabled is 50% opacity.
- **Field anatomy:** label (Label type) above, control, then hint or error in meta size, 6px apart. The hint and error are linked as the control's description, so its accessible name is the label alone.
- **Selects are native** `<select>` elements with a chevron drawn over them: they work without JavaScript and open the platform's picker on touch.
- **Checkbox:** a native 16px box with 4px corners; checked is Ink with a tick. **Switch:** a 36 by 20px pill, Ink when on.

### Notices

Standing information a person should not miss (an Order that needs attention, a Connection that must sign in again): a toned box with 8px corners, a 16px tone icon, an optional semibold title, body text in full foreground (never gray on a tint) and optional actions. The result of an action uses the same box as a form error (critical, `role="alert"`) or success (success, `role="status"`).

### Tables

- **Header row:** 36px, meta type at weight 500 in Muted Foreground on a 60% Muted fill.
- **Rows:** 44px minimum, 8px by 16px cell padding, hairline between rows, 60% Muted on hover. A row that leads to a detail page is clickable as a whole and its primary cell holds the real link.
- **Top-aligned variant** for rows whose cells hold forms or several lines: cells share the baseline of their first lines.
- **Numbers:** see The Tabular Rule. **Narrow behaviour:** see Layout.

### Filter Bar

A strip at the top of a list's card, over a hairline: **tabs** for mutually exclusive views (28px, 6px corners, meta type; the current one has an 8% foreground fill), **chips** for on/off filters (28px pills; off is a dashed outline in muted text, on is a solid outline with an 8% fill and a tick, so on is not told by fill alone), a compact select with its small label in front and an outline Apply button, a search field with a leading icon, and a ghost "Clear filters" shown only while a filter is active.

### Navigation

- **Sidebar:** the mark, the product name and the organization's name at the top; destinations grouped by job (Sales, Catalogue, Stock, Channels, Organization) under caption-size group labels in muted text, with the dashboard alone above the groups; the user menu at the foot. Items are 32px with a 16px muted icon. Hover fills with Sidebar Accent; the current item is a card-coloured tile with the Card shadow, medium weight and a full-foreground icon. An item with something waiting shows a count pill at its right (capped at "99+"), and the count is part of the link's accessible name in words. Collapsed to the icon rail, labels become tooltips and a count becomes a 6px dot on the icon.
- **Breadcrumbs:** group, destination, then named sub-pages. An id is never a crumb: from a detail page the destination crumb is the way back to the list.
- **Lists of links** (the dashboard's lists, a choice among connectors): whole-row links at least 44px high, a medium-weight title with a meta-size detail, an optional trailing count or badge, and a chevron. A zero count is muted so rows that hold something stand out.

### Command Palette

The signature interaction. Its trigger sits at the right of the top bar: an outline button 14rem wide showing a search icon, "Search" in muted text and a keyboard hint (Cmd+K on Apple platforms, Ctrl K elsewhere), shrinking to an icon button below 640px. It opens a dialog listing every destination from the same navigation model the sidebar and breadcrumbs read, and it finds Products by name or SKU, each result showing its SKU as an identifier at the right. A footer row explains the arrow, enter and escape keys. The scrolling list shades the edge that has more beyond it.

Orders are not searchable by number yet. This is a recorded gap, not a design choice: no core service looks an Order up by number.

### Empty and Page States

- **Empty state:** with a title, a centred block in the card: a 40px muted disc with a 20px icon, a semibold title, one sentence saying what to do next, and an outline action that does it. Without a title, one quiet line of muted text.
- **Page state** (not found, failed to load): the same block with the message as the page's `<h1>` and the ways out as buttons; the disc turns critical for a failure.

### Timeline

Events in time order: an 8px dot in Border Strong on a hairline rail, the event in body text, a meta-size detail line that may close with a link naming where it leads, and a caption-size timestamp in tabular figures.

## Do's and Don'ts

### Do:

- **Do** build screens from the kit in `src/components` (`Page`, `PageHeader`, `Section`, `Panel`, `DataTable`, `FilterBar`, `Notice`, `EmptyState`, the form kit) before reaching for a primitive in `src/components/ui`.
- **Do** style with tokens only: `bg-card`, `text-muted-foreground`, `border-border`, `text-<tone>`, `bg-<tone>-subtle`, `border-<tone>-border`.
- **Do** give every page exactly one `<h1>` through `PageHeader` and one primary button, top-right, or as the submit of a focused create or commit form.
- **Do** make every in-place save an outline button.
- **Do** state every state as tone plus icon shape plus text, through `Badge` or `Notice`.
- **Do** mark each table's primary cell, its end cell and its medium-hidden columns, and fold what a hidden column said into a `DataTableMeta` line.
- **Do** set identifiers with `Identifier`, Order numbers with `orderNumberClass`, missing values with `NoValue`, and numbers, money and dates through the formatters.
- **Do** take every user-facing string from `messages/en.json` and `messages/pl.json`, adding the key to both.
- **Do** give every control an accessible name; the end-to-end flows and screen readers both find elements by role and name.
- **Do** check every new screen in light and dark and at a narrow container width.

### Don't:

- **Don't** use raw palette classes, hex values, `white` or `black` in a screen.
- **Don't** hard-code copy in a component or an action, in either language.
- **Don't** put a second near-black button on a page. The Warehouses list's inline create form is the one recorded exception.
- **Don't** open a summary screen with KPI cards or totals; what needs a person comes first.
- **Don't** carry meaning by colour alone, and don't leave an icon off a badge unless it is a neutral tag.
- **Don't** nest a card inside a card.
- **Don't** use a hue for decoration or emphasis; colour is for links, focus and state.
- **Don't** set anything but identifiers in monospace, and don't set Order numbers in monospace or tabular figures.
- **Don't** write a negative number with a hyphen, or leave an empty cell where a value is missing.
- **Don't** size layouts from the viewport where the kit uses container queries; a table or a detail page must hold with the sidebar open or collapsed.
- **Don't** override the focus ring except to move it inside a clipped box.
- **Don't** ship raster images. This build ships none: the only image is the vector mark `src/app/icon.svg`, which predates the rebuild.
